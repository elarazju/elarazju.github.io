01 / 后训练 · 蒸馏↑ 667 赞

Waypoint-OPD

把老师学得稳定的部分，教给学生

Waypoint-OPD: Transferring RL-Induced Policy Shifts via Gated On-Policy Distillation

多看一个训练中间点，筛掉教师策略里前后反复的变化。

问题
只比较强化学习前后，无法判断某个偏好是否一直朝同一方向变化。
方法
加入一个冻结的中间检查点；前后两段变化越一致，蒸馏信号权重越高，方向相反则抑制。
结果
Qwen3 的 3 种学生规模 × 数学/代码两领域，共 6 组设置中，平均得分均优于所比较的蒸馏方法。
6 / 6组设置 · 域内均分领先比较方法

阅读边界 额外增加一次教师评分；实验集中在同模型家族与兼容 tokenizer，跨家族效果待验证。

02 / 多模态 · 评测↑ 577 赞

OmniCompass

看懂视频，还要说清何时、何地

OmniCompass: A Holistic Benchmark for Omni-Modal Video Grounding and Understanding

把视频问答、时间定位和空间定位放在同一套评测中。

问题
答对视频内容，不代表模型能正确指出证据出现的时刻和位置。
方法
设置视觉语言与音视频两条赛道，并对同一目标比较“文字”与“文字＋图像”两种提示。
结果
评测 50 个模型；精确时空定位仍是短板，音视频任务中开放模型与闭源模型的差距更明显。
50个模型接受统一评测

阅读边界 820 段视频中含 240 段音视频子集；有限数据与提示设置不等于全场景能力评估。

03 / 空间智能 · 高效推理↑ 353 赞

MJev-Spatial

空间判断，直接给出选择和坐标

MJev-Spatial: System One Spatial Intelligence via Native Attention Matching

把选项、数值和二维位置统一为分类，省去答案逐字生成。

问题
紧凑的空间答案也要自回归生成再解析，增加交互延迟。
方法
复用原有注意力的 Q/K 投影为候选打分；数值和位置由粗到细细分，每次分类只做一次前向。
结果
基于 Qwen3.5-4B，12 个基准平均分为 65.64%；在论文设置下，速度为原自回归基座的 5.6 倍。
5.6×论文设置下 · 相对原自回归基座

阅读边界 适合有限候选、数值和定位任务；多级细分仍需多次分类，不等于一次前向解决所有任务。

03 ARXIV / RECOMMENDER SYSTEMS

01 / 多目标 · 可控推荐编辑精选

RecSoup

让推荐目标，按需重新配比

RecSoup: Efficient Model Merging Approach for Controllable Multi-Objective Recommendation

把各目标专家模型先剪枝、再按偏好合并，实现推理时动态调整准确性与多样性的权衡。

问题
推荐目标会变化；固定权重难适应，临时生成整套模型参数又成本较高。
方法
按目标重要性与跨目标关联保留参数，再用轻量网络把偏好权重映射为合并系数。
结果
在 3 个离线基准中，参数构造相对超网络提速 165.9–228.8 倍；这不是整条推荐请求的提速。
165.9–228.8×仅参数构造阶段 · 相对超网络

阅读边界 适合已有同架构目标专家模型、需要频繁改变目标权重的推荐系统；线上收益仍需另行验证。

02 / 工业推荐 · 系统设计编辑精选

TransX

扩大推荐模型，复用历史计算

TransX Technical Report: Scaling Sequence Transduction for Recommendation

把历史行为编码与在线候选打分拆开，让大模型计算尽量被复用。

问题
推荐模型变大后，重复计算用户历史会让在线服务成本上升。
方法
将序列编码、行为记忆和候选融合分开扩容；离线预计算、近线刷新、在线读取记忆并预测。
结果
生产 A/B 中，核心模型相对 HSTU 基线的 CTR 提升 6.02%，转化提升 4.45%（均为相对提升）。
+6.02%CTR 相对提升 · 对比 HSTU 生产基线

阅读边界 适合有离线/近线基础设施的大规模推荐；行为记忆带来新鲜度、存储与故障恢复成本，扩展规律也只在已测设置内成立。

03 / 序列推荐 · 去偏编辑精选

PR-entmax

给长尾物品，更公平的竞争机会

Mitigating Popularity Bias in Sequential Recommendations with Sparse Prior-Regularized Objective

把流行度先验嵌入稀疏训练目标，让相关性与热门程度共同决定哪些物品参与更新。

问题
热门物品容易占据曝光；直接去偏又可能损害排序质量。
方法
仅替换损失函数，用带先验的稀疏概率映射训练；推理时移除先验，只按学到的相关性排序。
结果
SASRec / Tmall 上，NDCG@10 从 0.274 升至 0.285，目录覆盖率@10 从 0.351 升至 0.499。
0.351 → 0.499Coverage@10 · SASRec / Tmall

04 ARXIV / LLM & AGENTS

LLM / Agent · 能力、成本与评测

01 / Agent · 能力积累编辑精选

LAGO

把验证过的经验，变成可复用技能

LAGO: Language Agents with Reusable Growing Options

把通过验证的子任务 Agent 存入技能库，让后续任务复用整套执行流程。

问题
单个 Agent 包办长任务时，容易上下文过载；固定多 Agent 流程又难积累可复用能力。
方法
总控 Agent 分解任务，检索或新建执行 Agent；结果经验证后，符合新颖性要求的能力才入库，并持续去重。
结果
冻结 Qwen3.5-35B-A3B 权重，在 SWE-bench Verified 全量 500 题、单次尝试与官方 Docker 评测下，作者报告解决率 58.6%。
58.6%SWE-bench Verified · 全量 500 题

阅读边界 全量结果缺少同条件基线重跑；小规模消融尚不能完全分离技能复用的因果贡献。

02 / Agent · 能耗与成本编辑精选

Smaller, Greener?

模型是否更省，按成功任务算账

When Is Smaller Greener? Right-Sizing Language Models for Agentic AI

模型每次调用更便宜，并不保证 Agent 完成整项任务时更省。

问题
长任务会放大每一步的失误；失败、重试也消耗能量，单看每次调用成本会误判。
方法
以每个成功任务的能耗、成本和耗时选型；先排除全面落后的模型，再比较任务长度与目标权重。
结果
15 个开放权重模型、两类多步任务的试验显示，最佳能效模型随任务长度和类型改变；长任务可能更适合可靠的大模型。
15个开放权重模型 · 两类多步任务

阅读边界 目前仅为合成任务试验，使用单张 GPU 且只计显卡能耗；尚未验证跨任务的预测能力。

03 / LLM · 创造力评测编辑精选

q@Tail

测创造力，也测罕见场景的质量

Evaluating LLM Creativity through Long-Tail Performance

创造力不只看输出新不新，还要看模型在少见输入与输出组合上的质量。

问题
创造力基准题型和打分方式各异，难以解释究竟在测什么共同能力。
方法

结果

15 × 2615 个基准 × 26 个开放权重模型

阅读边界 表面词组稀有不等于语义创新；人类参考主要来自写作偏好，且无法完全排除通用能力影响。

05 ARXIV / TIME SERIES

时间序列 · 预测之外的三件事

近期编辑精选：生成完整路径、优化部署流水线、用多年数据验证季节性与漂移。覆盖方法、部署和评测。

01 / 时间序列 · 生成式预测编辑精选

PathFM

预测完整未来，而非孤立的时刻

PathFM: Fast Generative Forecasting of Multivariate Trajectories

用流匹配生成整段多变量未来路径，让累计需求、峰值和事件时间也能被预测。

问题
逐时刻的分位数预测没有说明各时刻如何联动，因此不足以可靠估计整段累计值或峰值风险。
方法
学习完整未来轨迹的联合分布，再把采样蒸馏到 1–2 步，并在多条样本间共享历史注意力缓存。
结果
作者在新建 fps-bench 上报告，两个模型规模的路径分数均领先所比较基线；常规边际预测也保持竞争力。
1–2 步蒸馏后的轨迹采样步数

阅读边界 路径比较依赖作者的评测设计及分位数基线补全方式；目前不支持文本等模态条件，混沌系统的长期分布仍有误差。

02 / 时间序列 · Agent 部署编辑精选

TimeRSI

让 Agent 持续打磨预测流水线

TimeRSI: Towards Self-Improved Agentic Deployment for Time-Series Foundation Models

冻结预测模型，由编程 Agent 根据历史误差改进输入处理、特征和输出修正。

问题
强大的零样本模型仍需要人工接入节假日、潮汐等任务知识，且同一流水线未必适合所有预测窗口。
方法
Agent 编写并回测流水线，按误差反复修订；部署时依据相似已完成窗口，选择历史表现较好的候选。
结果
覆盖 TIME 与 fev-bench 共 198 个任务；相对直接使用同一 TimesFM 3.0，TIME 的 MASE 降低 1.52%、CRPS 降低 1.61%。
−1.52%TIME 的 MASE · 相对直接使用同一基座

阅读边界 依赖清楚的任务及变量描述；历史回测收益不保证在分布变化后的未来仍然成立。

03 / 时间序列 · 数据与评测编辑精选

CESNET-TimeSeries26

用多年数据，区分季节与漂移

CESNET-TimeSeries26: A Multi-Year Network Traffic Time Series Dataset for Annual Seasonality, Concept Drift, and Long-Term Anomaly Detection

把时间序列评测拉长到多年，区分每年重复的季节变化与真正的异常和漂移。

问题
不足一年的数据看不到完整年度周期，容易把暑假、节日流量下降误当异常，也无法充分衡量跨年退化。
方法
发布 CESNET3 网络的 995 天主数据及约 4.5 年子网序列，按 10 分钟、小时、天聚合，并提供日历和基础设施事件信息。
结果
主数据覆盖 278,466 个 IP 地址、285 个机构和 566 个机构子网；作者分析显示该网络的年度季节性通常强于每周周期。
995 天主数据跨度 · 另含约 4.5 年子网序列

阅读边界 数据来自特定网络；长跨度子网仅含 TCP，不能直接与全协议流量比绝对规模；IP 地址也不等同于固定设备。
